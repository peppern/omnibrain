## Main Point

John O'Nolan's Claude Code workflow for big tasks: have one agent write a plan to markdown, then have a fresh agent critique it.

## Takeaways

- He finds planning mode only useful for small tasks.
- Ask Claude to write a plan in a markdown file, then kill that session.
- Start a new Claude and ask it to review the plan for needless over-engineering; it usually produces a much better plan.
- Optionally a third 'judge' Claude compares both plans against the codebase; he says it usually sides with the new plan.

## Original Post

> I find that Claude Code planning mode is only useful for really small tasks - for larger tasks what's working better for me:
> 
> Ask Claude to make a plan in a markdown file -- then promptly take that Claude out back and shoot it (ctrl+c)
> 
> Spin up a new Claude and tell it:
> 
> "a previous agent made [https://t.co/wgyEgb8O3v]. - please review this plan in detail and call out anything that appears to be overengineering needlessly for what should be a simple, robust system"
> 
> NewClaude generally is of the opinion that OldClaude was a total fuckhead, and subsequently comes up with a way better plan.
> 
> Optionally, you can spin up a 3rd Claude and ask it evaluate both plans in the context of the existing codebase - but I generally just find that JudgeClaude  agrees that OldClaude was a fuckhead and NewClaude's plan is the right way to go.
